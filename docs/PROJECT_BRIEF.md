# 项目背景与设计取舍

## 要解决的问题

简记·记账簿面向学生和上班族的日常收支场景，围绕三个任务组织体验：记下一笔、整理常用分类、回顾钱花在哪里。

这是项目的设计出发点，不代表已通过用户调研证明需求强度，也不使用未经测量的效率提升数据。

## 核心流程

记录收支 → 查看账单 → 预算管理与统计回顾。

分类管理与速记模板服务于这个流程：前者整理记录方式，后者减少相同信息的重复填写。

## 设计取舍

| 问题 | 选择 | 取舍理由 |
|---|---|---|
| 首页放多少信息 | 收支概览、账单与主要入口优先 | 首页便于记录和查看；更详细的分析放在统计页 |
| 如何处理重复收支 | 提供常用收支模板 | 复用分类与常用金额，同时保留修改空间 |
| 如何适应不同记账习惯 | 支持分类排序、隐藏和自定义 | 减少固定分类对个人习惯的限制 |
| 预算提醒后怎么操作 | 同时保留关闭和查看预算的选择 | 提醒提供下一步，也允许继续当前操作 |
| 如何保持页面一致 | 统一配色、文字层级、间距与顶部对齐 | 降低页面之间的视觉跳变 |

## 实现中关注的质量问题

- 金额计算：关注小数精度、汇总与预算判断的一致性。
- 数据更新：账单变更后，相关页面需要更新，避免统计与列表不一致。
- 图表：处理数据切换、异步绘制与失败后重试，避免旧画面覆盖新状态。
- 数据边界：区分本机账本与云端状态；没有真实验证的能力不标为已完成。

这些说明用于理解实现关注点，不提供内部代码、接口配置或部署方法。
